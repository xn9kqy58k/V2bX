# V2bX 日常使用说明

## 这是什么

V2bX 是节点端程序：它从面板读取节点与用户信息，启动对应的代理核心，再把流量等统计结果报回面板。
它不是面板本身。当前维护代码和更新入口是 [xn9kqy58k/V2bX](https://github.com/xn9kqy58k/V2bX)。

## 面板兼容

本项目继承上游 V2bX 的面板接口，原项目要求搭配其[修改版 V2board](https://github.com/wyx2685/v2board)。
这个面板是独立项目，不会随本仓库自动复制、安装或升级。其他面板能否使用，要看节点接口是否兼容；不要只根据项目名称判断。

## 准备配置

从 [example/config.json](../example/config.json) 了解配置结构，再按自己的环境修改：

- `Log`：日志级别和日志文件位置。`Output` 留空时使用程序默认输出；指定文件失败时会回退到标准输出。
- `Cores`：需要启动的核心，例如 `sing`、`xray`、`hysteria2`。编译时必须包含相应核心。
- `Nodes`：面板地址、面板密钥、节点编号、节点类型、监听地址和证书设置等。

样例中的面板地址、密钥、节点编号和证书域名只是示例，不能原样用于自己的服务器。
样例中的 `OriginalPath` 指向额外的核心配置文件；只有确实准备了这个文件时才保留该项，否则按实际需要删除或修改。
证书文件、DNS 配置和核心原始配置文件的路径，需要能被程序或容器访问。

## 启动和查看版本

```sh
V2bX version
V2bX server --config /etc/V2bX/config.json
```

程序默认监视配置变化。保存配置后会等待约 5 秒再尝试重载，并保留原有的约 10 秒事件节流。
JSON 解析失败时保留上一份正常配置，不调用节点重启；修正后再次保存，等待下一次有效变更被处理。
这不能代替检查配置内容是否适合自己的面板、协议和证书。

## 更新现有服务

1. 备份现有程序及 `/etc/V2bX`，记录原来的程序位置和服务名称。
2. 从[本仓库的构建页面](https://github.com/xn9kqy58k/V2bX/actions/workflows/release.yml)取得对应系统与 CPU 的程序，或按 README 从源码构建。
3. 停止原服务，替换程序，确认执行权限和配置路径，再用原来的服务管理方式启动。
4. 检查 `version` 输出和启动日志，确认节点正常连接面板。

如果使用 systemd，单元名称以实际安装为准。Docker 部署需要使用新镜像重建容器，并保留配置目录挂载。

## 日志排查

启动失败时先检查：配置文件是否能读取、面板地址与密钥是否正确、节点端口是否被占用、证书文件是否存在。
日志文件路径不可写时，程序会把错误和后续日志输出到标准输出；systemd 或 Docker 的日志功能通常可以继续收集这些输出。

Linux 内核漏洞的检查、临时缓解和升级说明见 [CVE-2026-98432 处理说明](security/CVE-2026-98432.md)。
